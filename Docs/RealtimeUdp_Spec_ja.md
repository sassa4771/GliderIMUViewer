# RealtimePreview UDP 通信仕様

`Assets/Scenes/RealtimePreview.unity` が受信するデータの仕様と、受信後の扱い（姿勢への変換・ゼロ点・IMU の取り付け向き）をまとめたものです。
実装の手順やトラブル対応は [RealtimeUdp_ja.md](RealtimeUdp_ja.md) を参照してください。

## 1. 全体像

```
機体 (XIAO + 親機ESP32) ──ESP-NOW──> 子機ESP32 ──USBシリアル──> PC の Python ──UDP──> Unity (RealtimePreview)
```

- 通信は **Python → Unity の一方向**です。Unity から返信や確認応答は送りません。
- Unity は届いたサンプルをその都度モデルの姿勢に反映します。送信側は接続や開始の手続きなしに、送りたいときに送るだけです。

## 2. トランスポート

| 項目 | 仕様 |
|---|---|
| プロトコル | UDP |
| ポート | **9000**（既定。再生中に画面右上の `UDP port` で変更可） |
| 待ち受けアドレス | 全インターフェース。IPv4 は必須、IPv6 は使える環境でのみ併用 |
| 宛先 | 同じ PC なら `127.0.0.1`。別 PC なら画面の `this PC:` に出るアドレス |
| 単位 | 1 メッセージ = 1 データグラム（テキスト形式は 1 データグラムに複数行も可） |
| 文字コード | UTF-8。末尾の改行・先頭の BOM はあってもなくてもよい |
| 最大サイズ | 65536 バイト |
| 送信レート | 任意。現行ファームは **30 Hz**。1 秒以上途絶えると `NO DATA` 表示になる |

UDP なので、欠落・順序の入れ替わり・重複が起こり得ます。Unity 側はそれを前提に作ってあります（4 章）。

## 3. メッセージ形式

形式はデータグラムごとに自動判別します。どれを使ってもかまいません。

### 3.1 シリアルの行そのまま（推奨）

子機 ESP32 がシリアルに出す行を、加工せずに送ります。行頭の `HDR` / `DAT` / `LOG` は大文字小文字を区別しません。

| 行 | 書式 | 役割 |
|---|---|---|
| `HDR` | `HDR,1,GLDR,fields=<名前>,<名前>,...[,rate=30]` | `DAT` の値の並びを宣言する。`fields=` 以降を名前として読み、`key=value` 形式のトークンが来たらそこで打ち切る |
| `DAT` | `DAT,<seq>,<t_ms>,<値>,<値>,...` | 1 サンプル。値は直近の `HDR` の順に名前が付く |
| `LOG` | `LOG,<文字列>` | 機体からのメッセージ。画面左上のパネルに表示 |

```
HDR,1,GLDR,fields=dt_ms,ax,ay,az,gx,gy,gz,roll,pitch,yaw,s0,s1,s2
DAT,1234,56789,33.333,0.010,-0.020,1.000,0.100,-0.200,0.300,1.500,-2.300,180.000,85.000,105.000,70.000
LOG,mode:Manual
```

`DAT` の各項目:

| 項目 | 意味 | Unity での用途 |
|---|---|---|
| `seq` | サンプルの通し番号（1 ずつ増える） | 欠落数（画面の `lost`）の計算 |
| `t_ms` | 機体側の時刻 [ms] | グラフの時間軸、機体の再起動の検出 |
| `roll` `pitch` `yaw` | 姿勢角 [度] | **モデルの姿勢とグラフ** |
| `s0` `s1` `s2` | サーボ角 | 左上のパネルに数値表示 |
| `dt_ms` `ax` `ay` `az` `gx` `gy` `gz` | 周期・加速度・角速度 | 受信するが表示には使わない |

- `HDR` を一度も受け取っていない間は、上の例の並び（現行ファームの並び）を仮定します。並びを変えたファームでは `HDR` が必須なので、**`HDR` は数秒ごとに送り直してください**。
- `nan` / `inf` / `ovf` と書かれた値は、その値だけ「なし」として扱います。
- `LOG` のうち `mode:<値>` と `Param:<値>` はパネルの専用行に出ます。画面のフォントの都合で、ASCII 以外の文字は `?` に置き換え、160 文字を超える分は切り捨てます。

### 3.2 JSON

```json
{"seq": 1234, "t_ms": 56789, "roll": 1.5, "pitch": -2.3, "yaw": 180.0, "s0": 85.0}
```

- `roll` `pitch` `yaw` のどれかがあればサンプルとして扱います。`seq`（または `src_seq`）と `t_ms` は任意です。
- 入れ子のオブジェクトは `fields.roll` と `roll` の両方の名前で引けます。
- LOG は `{"log": "mode:Auto"}`、または `{"type": "log", "msg": "..."}`。
- `NaN` / `Infinity` はその値だけ読み飛ばします。数値が文字列（`"1.5"`）でも読みます。
- 数値だけの配列 `[1.5, -2.3, 180.0]` は 3.4 と同じ「位置で対応付け」になります。

### 3.3 OSC

| 項目 | 仕様 |
|---|---|
| アドレス | `/plane/data`（これ以外は無視。Inspector の `Osc Address Filter` で変更可） |
| 引数 | 位置で `roll, pitch, yaw, sv1, sv3` に対応付け。float / int / double を数値として読む |
| 条件 | 数値が 3 つ以上あること。バンドルも可 |

`viewer_serialsend.py` の既存の OSC 出力がこの形式です。`seq` と `t_ms` がないため、欠落数は数えられず、グラフの時間軸は受信時刻になります。

### 3.4 数値だけ / key:value

```
1.5,-2.3,180.0                    位置で roll, pitch, yaw（数値 3 つ以上。区切りはカンマ・空白・タブ・セミコロン）
roll:1.5,pitch:-2.3,yaw:180.0     名前付き（roll=1.5 pitch=-2.3 の書き方も可）
```

## 4. 受信側の動作

| 状況 | 動作 |
|---|---|
| `roll` `pitch` `yaw` の一部しか入っていない | 来なかった成分は前回の値のまま |
| `seq` が 2〜1000 飛んだ | 飛んだ分を `lost` に加算 |
| `seq` が戻った、または 1000 より大きく飛んだ | 送信側の切り替わりとみなし、`lost` には数えない |
| `t_ms` が 1 秒より大きく戻った | 機体の再起動とみなし、方位のゼロ点だけ取り直す |
| 角度の絶対値が 3600 度を超える | そのサンプルを無視（フィールドの並び違いとみなす）。画面に `values out of range` と出る |
| 名前付き形式（DAT / JSON / key:value）と OSC・数値だけの形式が同時に届く | 名前付きが届いてから 1 秒間は、OSC・数値だけの形式を無視する |
| 読めないデータグラム | 無視して `unreadable` に加算。理由を状態行に表示 |
| 1 秒以上サンプルが来ない | `NO DATA` 表示。モデルは最後の姿勢のまま |
| 処理が追いつかない（待ち行列が 2048 件を超える） | 古いものから捨てて `dropped` に加算 |

状態行の表示:

| 表示 | 意味 |
|---|---|
| `WAITING` | 待ち受け中で、まだ何も届いていない |
| `LIVE <レート> Hz from <送信元> [形式]` | 受信中 |
| `NO DATA <秒数> s` | 受信が途絶えている |
| `NO ATTITUDE <理由>` | 何か届いているが、姿勢として読めていない |
| `ERROR <理由>` | ポートを開けなかった（他のアプリが使用中など） |
| `PAUSED` | 表示を一時停止中（受信と統計は続く） |

## 5. 角度の定義

- 単位は**度**です（ラジアンで送る場合は `RealtimePoseStore` の `Angles Are Radians` を有効にする）。
- ファームウェアが使う Madgwick ライブラリの定義に従い、**yaw → pitch → roll の順**に合成します（`R = Rz(yaw)·Ry(pitch)·Rx(roll)`、IMU の Z 軸が上の右手系）。
- roll は IMU の X 軸まわり、pitch は Y 軸まわり、yaw は Z 軸まわりの回転で、いずれも右ねじの向きが正です。
- 現行ファームの yaw は 180 を足した 0〜360 の値で届きます。画面では、ゼロ点を取った時点を 0 とした ±180 の値で表示します（6.2）。

## 6. 画面下のボタンの意味

### 6.1 `IMU X: tail` / `IMU X: nose` / `Legacy map`（IMU の取り付け向き）

roll と pitch は「IMU の軸まわりの回転」なので、**IMU が機体にどちら向きに付いているか**で、同じ受信値でも実機の動きが逆になります。このボタンは、その取り付け向きを Unity に教えるためのものです。押すたびに `IMU X: tail` → `IMU X: nose` → `Legacy map` と切り替わります。

機体モデルは、胴体が Unity の Z 軸（機首が -Z）、翼幅が X 軸、上が Y 軸です。

| 表示 | 想定する取り付け | roll が増えると | pitch が増えると | yaw が増えると |
|---|---|---|---|---|
| `IMU X: tail`（既定） | IMU の +X が**機尾**向き | 右翼が上がる | 機首が上がる | 機首が左へ回る |
| `IMU X: nose` | IMU の +X が**機首**向き | 右翼が下がる | 機首が下がる | 機首が左へ回る |
| `Legacy map` | KinematicPreview シーンと同じ計算 | （下の注） | （下の注） | 機首が左へ回る |

`tail` と `nose` の違いは、IMU を上から見て 180 度回して付けたかどうかです。そのため roll と pitch の符号が両方とも反転し、yaw は変わりません。

**どちらを選ぶか**

- 既定を `IMU X: tail` にしてあるのは、現行ファームが発射を「X 軸の加速度が負に振れたこと」で検出しているためです（前に加速して X が負になるなら、+X は機尾向き）。これは**ファームからの推定で、実機では未確認**です。
- 同梱のサンプル CSV（`out_20250912-152517.csv`）を記録した機体は、逆の `IMU X: nose` の向きでした。
- **確認方法**: 実機を手に持ち、機首を上げ、次に右翼を下げます。画面のモデルが同じ動きをすれば合っています。逆に動く場合はボタンを押して切り替えてください。

**`Legacy map` について**

KinematicPreview シーンと同じ割当（roll → Unity の X 軸、pitch → Z 軸、合成は `Quaternion.Euler`）です。このモデルでは X 軸が翼幅方向なので、**受信した roll が機首の上げ下げとして、pitch が翼の傾きとして表示されます**（roll と pitch が入れ替わって見える）。CSV 再生シーンと見え方を揃えたいとき用に残してあります。

**設定の保存**

ビルドしたアプリでは、選んだ向きを次回起動時も引き継ぎます。Editor では引き継がないので、既定を変える場合は `RealtimePoseStore` コンポーネントの右クリックメニュー `Axis preset: ...` を選んでシーンを保存してください。

### 6.2 `Zero` と `Zero: Yaw` / `Zero: Level` / `Zero: Off`（ゼロ点）

`Zero`（または Z キー）は、その瞬間の姿勢を基準に取り直します。何を基準にするかは隣のボタンで切り替えます。

| 表示 | 動作 | 使いどころ |
|---|---|---|
| `Zero: Yaw`（既定） | 機首方位だけを 0 にする。roll・pitch は受信値のまま | 通常はこれ。yaw はジャイロ積分でずれていくので、ずれたら `Zero` を押す |
| `Zero: Level` | 方位に加えて、`Zero` を押したときの傾きを「水平」とみなす | IMU が機体に対して少し傾いて付いていて、水平に置いても roll・pitch が 0 にならないとき。機体を水平に置いて `Zero` を押す |
| `Zero: Off` | 補正なし。受信値をそのまま表示（yaw は 0〜360 のまま） | 受信値そのものを確認したいとき |

- 最初のサンプルを受け取った時点で、自動的に一度ゼロ点を取ります。
- 機体の再起動を検出したときは、方位のゼロ点だけを取り直します（`Zero: Level` の傾きの補正は保たれます）。
- 補正前の受信値は、左上のパネルの `recv` 行でいつでも確認できます。

### 6.3 その他

| 操作 | 内容 |
|---|---|
| `Pause` / Space | 表示の一時停止・再開（受信は続く） |
| グラフの `Roll` / `Pitch` / `Yaw` をクリック | その線の表示・非表示 |
| `UDP port` + `Set` | 待ち受けポートの変更 |
| F1 | UI の表示・非表示 |

## 7. テスト送信ツールの出力の読み方

`python Tools/udp_test_sender.py` は、機体と同じ **30 Hz（1 秒に 30 サンプル）** で `DAT` 行を送ります。コンソールの表示は進捗で、**1 秒に 1 行**だけ出ます。

```
[   1.0s] samples=32 sent=35 dropped=0  last: DAT,32,1033,33.333,...
```

| 項目 | 意味 |
|---|---|
| `[ 1.0s]` | 開始からの経過時間 |
| `samples` | これまでに送った `DAT` サンプルの累計（1 秒あたり約 30 ずつ増える） |
| `sent` | 送ったデータグラムの累計。`HDR` と `LOG`（それぞれ 2 秒ごと）を含むので `samples` より多い |
| `dropped` | `--loss` で意図的に捨てた数（指定しなければ 0） |
| `last:` | 最後に送った 1 件の中身（先頭 90 文字） |

送信レートは `--rate 50` のように変更できます。全データグラムを表示したい場合は `--print` を付けてください。

## 8. 最小の送信例（Python）

```python
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
UNITY = ("127.0.0.1", 9000)

# シリアルから 1 行読むたびに、そのまま送る
line = ser.readline().decode("utf-8", errors="ignore").strip()
if line.startswith(("HDR,", "DAT,", "LOG,")):
    sock.sendto(line.encode("utf-8"), UNITY)
```
